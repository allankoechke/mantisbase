C++ Dev Package

Use MantisBase as a prebuilt C++ library in your own application — no submodule, no waiting on a full source build. This guide covers downloading the package, wiring it into your build, and running your app.

Building from source or embedding via submodule instead? See the Embedding Guide. For the server binary or Docker, see the Installation Guide.

What you get

Each GitHub release ships one C++ dev package per OS (shared library only, no static archives):

File Contents

mantisbase_<tag>-darwin-cpp-dev.zip libmantisbase.dylib for Intel (libs/x86) and Apple Silicon (libs/arm) + macOS headers

Prerequisites

Linux — the shared library needs its system dependencies at build and run time:

sudo apt-get update
sudo apt-get install -y libpq-dev uuid-dev

(Runtime packages on Debian/Ubuntu are libpq5 and libuuid1.)

Windows (MinGW) — no extra packages. The socket/RPC/IP-helper/crypto system libraries (ws2_32, rpcrt4, iphlpapi, crypt32) are linked automatically.

macOS — the shared library needs its system dependencies at build and run time:

brew install libpq ossp-uuid

Toolchain — C++20 compiler (GCC/MinGW 13+, Apple Clang 15+) and CMake 3.22+.

Integration

Option A: find_package (recommended)

# cmake -B build -DCMAKE_PREFIX_PATH=/path/to/mantisbase-linux-cpp-dev
find_package(MantisBase REQUIRED)
target_link_libraries(my_app PRIVATE mantisbase::shared)

A version can be requested: find_package(MantisBase 0.4 REQUIRED).

The right libs/<arch>/ binary is picked automatically for your CPU.

Option B: manual (without CMake)

Linux — make sure the .so is findable at runtime (via rpath or LD_LIBRARY_PATH):

g++ -std=c++20 main.cpp -I path/to/include -L path/to/libs/x86 -lmantisbase -Wl,-rpath,path/to/libs/x86 -lpq -luuid -ldl -lpthread -lm -o my_app

Windows (MinGW) — keep libmantisbase.dll next to your .exe at runtime:

target_include_directories(my_app PRIVATE path/to/include)
target_link_libraries(my_app PRIVATE path/to/libs/x86/libmantisbase.dll.a ws2_32 rpcrt4 iphlpapi crypt32)

macOS — make sure the .dylib is findable at runtime (via rpath):

# Example: Apple Silicon, shared
clang++ -std=c++20 main.cpp -I path/to/include -L path/to/libs/arm -lmantisbase -Wl,-rpath,path/to/libs/arm -lpq -luuid -ldl -lpthread -lm -o my_app

#include <mantisbase/mantisbase.h>

Troubleshooting

Symptom Cause / fix
MantisBase dev package does not support '<system>' You unzipped the wrong OS package — download the -linux-cpp-dev, -windows-cpp-dev or -darwin-cpp-dev zip matching your machine.
MantisBase shared library not found: '.../libs/<arch>/...' No binary for your CPU in this package (e.g. 32-bit). Check libs/ for shipped architectures, or build from source.
MantisBase requires libpq / libuuid (Linux/macOS) Install libpq-dev and uuid-dev on Linux, libpq and ossp-uuid (Homebrew) on macOS (see Prerequisites).
App builds but fails to start: libmantisbase.so: cannot open shared object file The loader can't find the .so — set LD_LIBRARY_PATH or link with -Wl,-rpath,<libs dir>.
App builds but fails to start on Windows (0xc0000135 / missing DLL) Copy libmantisbase.dll next to your .exe.
find_package reports a version mismatch Request a compatible version (find_package(MantisBase 0.4 REQUIRED)); on 0.x releases minor versions must match.

Notes

  • Dev packages ship shared libraries only. If you need static linking (single-binary deployment), build from source instead.
  • The bundled third-party headers (drogon/, trantor/, soci/, ...) are part of the package — don't mix them with system-installed copies.
  • SOCI is bundled inside the shared library (SQLite + PostgreSQL backends) — no extra SOCI install needed. MbDatabase::session() returns a soci::session you can query directly with <soci/soci.h>; linking -lmantisbase alone is enough:
    #include <mantisbase/mantisbase.h>
    #include <soci/soci.h>
    auto sql = app->db().session();
    int count = 0;
    *sql << "SELECT COUNT(*) FROM my_table", soci::into(count);
  • Only soci_core is exported: get sessions from MbDatabase::session()/connectionPool() rather than opening backend sessions yourself (soci::session(soci::sqlite3, ...)), and catch soci::soci_error instead of backend-specific error types.
  • libpq-fe.h / uuid.h are system headers and are intentionally not bundled.
